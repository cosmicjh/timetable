# 자료 이관과 대조

## 기존 JSON 백업이 있는 경우

1. 기존 운영 서비스에서 새 백업을 다운로드합니다. 원본 JSON·엑셀은 보관하고 삭제하지 않습니다.
2. 파일을 `private/before.local.json`처럼 Git 제외 위치에 둡니다. 기존 형식은 `format: school-timetable-backup`, `schemaVersion: 1`, 본문은 `store`입니다. store는 term·settings·students·sections·teacherRows·overrides·blocks를 포함합니다.
3. 먼저 로컬 D1에 복원하여 검증합니다. 관리자 → 설정에서 백업과 같은 학년도·학기를 생성/선택하고, 변경 이력 → 백업 불러오기로 JSON을 선택합니다. 다른 학기 백업의 복원은 서버가 거부합니다.
4. 학생·분반 내부 ID, sourceKey(원본학번), manualFields(웹 수정 항목), 학적, 과목별 choices, 수동 연결·시간블록을 유지합니다. 빈 과목 배정도 보존합니다. 기존 시트 행 위치인 _row는 D1의 행 주소로 사용하지 않습니다.
5. 복원 후 백업 저장을 눌러 `private/after.local.json`에 보관하고 아래 대조를 실행합니다.

```sh
pnpm compare:backups private/before.local.json private/after.local.json
```

이 명령은 두 파일을 읽기만 하며 학생 이름이나 원자료를 출력하지 않습니다. 학생·재학생·분반·실제 수강 배정·교사·수동 연결·블록 건수와 학생 정보/원본학번/학적/수정 보호/배정/ID의 해시, 모든 재학생 시간표·교사 시간표·선택분반 명렬표 결과의 해시를 비교합니다. `equal: true`와 종료 코드 0이 완전 일치입니다. 학생 수정일·백업 생성일·_row는 비교에서 제외합니다. 결과가 다르면 원인을 확인하기 전 운영 전환을 하지 않습니다.

로컬 검증 후 새 원격 D1에 동일 백업을 복원하고 새 백업을 다시 다운로드하여 같은 대조를 실행합니다. 실제 학생과 교사가 사용하는 표본 시간표·명렬표·교실·2+1수업·공강도 화면에서 확인합니다. 새 DB의 교사·관리자 비밀번호는 이전 Apps Script 비밀번호와 별개이며 관리자 설정에서 새로 지정합니다.

## 백업이 없는 경우

관리자 → 자료 등록에서 기존 5개를 사용합니다.

1. 전체교사시간표 1개.
2. 선택과목정보 1개: 학년·선택반명·교과명·수업교실·축약과목명 열.
3. 학생 배정 3개: 기존 학년별/3학년 2단위·3단위 자료. 학년·반·번호·이름 또는 학번·이름 열과 과목별 분반 코드.

학생 배정 입력에서 3개를 함께 선택합니다. 학교에서 주는 전체교사시간표의 행·열을 바꿀 필요가 없습니다. 원본 Core의 헤더 감지로 월~금과 교시 열, 2행씩의 교사 과목·교실을 읽습니다. 미리보기의 오류·동일 학생 과목 충돌·모호한 학번 연결을 해결한 후 등록합니다. 여러 학생 파일의 같은 학생은 원본학번으로 합치고 이름/과목 배정 충돌은 거부합니다.

전체교사시간표만 교체할 때에는 해당 파일만 선택합니다. 학생·수강 배정·분반·학적은 건드리지 않습니다. 전체 재등록은 기본 ‘웹 수정값 유지’를 유지합니다. 수정한 학생의 이름·반·번호·비고·수강분반과 전출·자퇴·휴학 상태를 되돌리지 않습니다. 누락된 기존 학생과 분반도 유지하여 수동 수정의 연결을 보호합니다. 변경한 분반 교실·축약명도 보존합니다.

이전 백업 없이 엑셀로 처음 등록하면 원래 서버의 내부 ID를 알 수 없으므로 새 ID를 부여합니다. 기존 ID까지 보존해야 한다면 먼저 기존 서비스의 JSON 백업을 받아야 합니다. 최초 엑셀 등록 이후에는 재등록·학급 변경에도 ID를 유지합니다.

초기 등록 후 새 백업을 반드시 다운로드합니다. 이후 복원과 대조는 같은 v1 형식으로 동작합니다. 별도 Google 연결 설정이나 API 키는 필요하지 않습니다.

## 이번에 수행한 범위

가상 v1 백업을 실제 로컬 D1에 복원하고 학생·분반·배정 건수 및 Core.gs의 원본 시간표·명렬표 결과를 비교했습니다. 엑셀 5개는 브라우저에서 가상 XLSX를 생성해 실제 파일 업로드→미리보기→등록까지 검증했습니다. Desktop의 실제 전체교사시간표는 읽기 전용으로 헤더 감지만 확인했으며 64명, 월/화/목/금 7교시·수요일 6교시를 인식했습니다. 해당 파일의 개인 자료를 저장소나 공개 파일에 복사하지 않았습니다.

실제 학생 배정 파일 3개·선택과목정보·기존 운영 JSON 백업은 이 작업에 제공되지 않았습니다. 실제 학생 자료의 로컬/원격 이관과 이관 전후 운영 결과 대조는 수행하지 않았습니다. 기존 Apps Script·스프레드시트·GitHub Pages는 그대로 남아 있습니다.
